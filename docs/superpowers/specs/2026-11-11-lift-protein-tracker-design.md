# Lift and Protein Tracker — React App Design

**Date:** 2026-11-11  
**Status:** Draft, pending user review

---

## Overview

Convert the existing single-file HTML prototype (`index.html`) into a maintainable React app that is feature-identical to the prototype, installable as a PWA, and structured so that domain logic, storage, and UI are independently changeable. Hosted on Vercel.

---

## Stack

| Concern | Choice | Reason |
|---------|--------|--------|
| Bundler | Vite | Fast HMR, first-class PWA plugin |
| UI | React 18 + TypeScript | Specified |
| Styles | Plain CSS (design tokens from prototype) | No UI library |
| State | Zustand | Selector-granular re-renders keep inputs stable; clean subscription for storage adapter |
| Tests | Vitest | Vite-native, fast |
| PWA | vite-plugin-pwa (Workbox generateSW) | Zero-config service worker + manifest |

## Domain Types (`src/domain/types.ts`)

```typescript
export interface SetEntry {
  r: number | null;   // reps logged (null = not entered)
  d: boolean;         // marked done
}

export interface ExerciseEntry {
  w: number;          // weight in lb (0 = bodyweight)
  sets: SetEntry[];
}

export interface ProteinItem {
  id: string;
  fid?: string;       // food list id if from the list
  n: string;
  g: number;
}

export interface DayRecord {
  wk?: string | null; // 'tue' | 'wed' | 'thu' | 'off' | null (null = auto from weekday)
  warm: Record<string, boolean>;
  cool: boolean;
  ex: Record<string, ExerciseEntry>;
  bike: boolean;
  sit: string;
  push: string;
  items: ProteinItem[];
  meals: Record<string, boolean>;
  bw: string;
  photos: Array<{ id: string; t: number }>;
  u: number;          // last-updated timestamp (ms since epoch)
  // carry-forward dial values (may be absent; pref() walks back to find them)
  rowMin?: number;
  walkMin?: number;
  walkInc?: number;
  walkSpd?: number;
  bikeMin?: number;
}

export interface AppData {
  days: Record<string, DayRecord>;   // keyed YYYY-MM-DD
  target: number;                    // protein goal in grams
  targetUpdated: number;             // timestamp for merge priority
}
```

## Domain Logic

### `plan.ts`
Exports the static constants copied verbatim from the prototype: `WK`, `WARM`, `FOODS`, `CATS`, `MEALS`, `IDEAS`, `NEXTUP`, `ALLEX`, `exById()`.

### `progression.ts`
```typescript
// Returns last session where any set was marked done, searching backwards from date.
function lastSess(days, date, exerciseId): { date, w, sets } | null

// Returns suggested weight and whether it is a bump.
// Bump fires when every done set >= e.hi and e.inc is set.
function sugg(days, date, exercise): { w: number; up: boolean; last: ReturnType<typeof lastSess> }

// Returns the existing ExerciseEntry for this day+exercise, or creates a fresh one.
// NEVER mutates days; callers must replace the entry in a cloned day.
function ensure(day, exercise): ExerciseEntry
```

### `pref.ts`
```typescript
// Walks days backwards from (but not including) date to find the most recent
// non-null value for key. Returns def if none found.
function pref(days, date, key, def): number
```

### `protein.ts`
```typescript
function protTotal(day: DayRecord): number
function nextUp(day: DayRecord): FoodItem[]   // top-3 not yet logged
function summaryText(days, date, target): string  // copy-check-in text
```

### `stats.ts`
```typescript
// Returns the 14 YYYY-MM-DD keys ending on date (inclusive).
function last14(date: string): string[]

function didLift(day: DayRecord | undefined): boolean
function didBike(day: DayRecord | undefined): boolean
function hitProtein(day: DayRecord | undefined, target: number): boolean
```

### `merge.ts`
```typescript
// Merges imported data into current data.
// Per-day: the record with the larger .u timestamp wins.
// target: the record with the larger targetUpdated wins.
// Returns a new AppData object; never mutates either input.
function merge(current: AppData, incoming: AppData): AppData
```

## Storage Adapter

### `storage/adapter.ts`

```typescript
export interface StorageAdapter {
  load(): Promise<AppData>;
  save(data: AppData): Promise<void>;
  loadBlob(id: string): Promise<Blob | null>;
  saveBlob(id: string, blob: Blob): Promise<void>;
  deleteBlob(id: string): Promise<void>;
}
```

### `storage/local.ts`

- `load` / `save`: JSON in `localStorage` under key `lpl-v1`. Clone on load to prevent read-only mutation bugs.
- `loadBlob` / `saveBlob` / `deleteBlob`: IndexedDB object store `blobs`, keyed by photo id.
- Saves are debounced 800 ms in the store subscription (not in the adapter itself).

### Actions (all immutable — clone before mutating)

**Navigation / UI** (kept in component `useState`, not the store):

- `toggleCool(date, checked)`
- `setReps(date, exId, setIndex, value)`
- `toggleSetDone(date, exId, setIndex)`
- `adjustWeight(date, exId, direction)` — direction: +1 or -1, step = e.inc
- `adjustSetCount(date, exId, direction)` — clamps 1–8
- `adjustDial(date, key, direction, step, min, max)`

**Daily activities**
- `toggleBike(date, checked)`
- `setSitUps(date, value)`
- `setPushUps(date, value)`

**Photos**
- `addPhoto(date, photoId)` — blob already saved via adapter before this is called
- `removePhoto(date, photoId)`

**Protein**
- `addProteinItem(date, item)`
- `removeProteinItem(date, itemId)`
- `toggleMeal(date, mealId, checked)`
- `setProteinGoal(grams)`

**Body weight**
- `setBodyWeight(date, value)`

**Import / Export**
- `importData(incoming: AppData)` — runs merge(), then saves
- `exportData(): AppData` — returns a snapshot (no blobs)

### Persistence subscription

```typescript
useStore.subscribe(
  state => ({ days: state.days, target: state.target, targetUpdated: state.targetUpdated }),
  debounce(snapshot => adapter.save(snapshot), 800)
);
```

## Component Details

### Inputs and focus stability

Rep inputs are **uncontrolled**: `<input defaultValue={set.r ?? ''} onChange={...} />`. The `onChange` calls `setReps` which updates the store, but because the input is uncontrolled it does not re-render from the store value — the user keeps focus and cursor position. `setReps` does not trigger a re-render of the input's parent if the selector is scoped to only the done/d field.

Sit-ups, push-ups, body weight, protein goal, and custom food inputs follow the same pattern.

### ExerciseCard

Subscribes only to `days[date].ex[exId]` and the exercise plan object. Does not re-render when other exercises change. Displays:
- Weight stepper
- Sets-today stepper (1–8)
- SetGrid (reps inputs + done toggles)
- Progression tip (bump suggestion, or last-session summary)

### SetGrid

Renders one cell per set: a text input (uncontrolled, `inputmode="numeric"`) and a done toggle button. Done toggle reads the rep input's current value before toggling — if the input is populated and not yet saved to the store, it saves it first.

### PhotoCard / PhotoViewer

PhotoCard: shows the 3-column grid plus an Add button. Reads photos from `days[date].photos`. Add button triggers a hidden `<input type="file" multiple accept="image/*">`. On change:
1. For each file: resize to max 1600 px JPEG at 0.82 quality (canvas approach from prototype).
2. Save blob via `adapter.saveBlob(id, blob)`.
3. Dispatch `addPhoto(date, id)`.

PhotoViewer: a fixed overlay. Two-tap delete: first tap sets `pendingDelete` local state and changes button label; second tap calls `removePhoto` + `adapter.deleteBlob`. Escape key closes. `role="dialog" aria-modal="true"`.

### Stepper (shared)

```tsx
<Stepper
  value={n}
  onDecrement={() => ...}
  onIncrement={() => ...}
  label="Sets today"       // screen reader label
  min={1}
  max={8}
/>
```

Min/max props disable the respective button (not just visually — `disabled` attribute). 44 px minimum touch target on each button.

### Charts

**SparkLine**: inline SVG, `aria-hidden="true"`. Renders a polyline + dot at the last point, same geometry as the prototype.

**BodyWeightChart**: inline SVG with `role="img"` and an `aria-label` that includes the range (e.g. "Body weight from 182.0 to 178.5 lb"). Same geometry as prototype. Renders only when ≥ 2 data points exist.

**DotGrid**: 3 rows × 14 columns of `<span>` elements. The row labels ("Lift", "Bike", "Protein") are plain text; day-of-week labels are above. No SVG needed.

## Data Tab (`components/data/Data.tsx`)

A fourth bottom-tab item labelled **Data**. Contains:

- Brief note: "Your logs live on this device. Export a backup before switching browsers or devices. Photos are stored separately and are not included in the JSON export."
- **Export JSON** button: serializes `{ days, target, targetUpdated }` and triggers a browser download as `lpl-backup-YYYY-MM-DD.json`.
- **Import JSON** button: opens a file picker, reads the selected file, parses it, runs `merge(current, incoming)`, updates the store, and saves. The merge uses per-day timestamps so neither side loses newer data. Shows a toast on success or error.

The tab is intentionally minimal — it's a utility screen, not a primary workflow.

## Data Pitfalls (from prototype)

1. **Read-only data from localStorage**: `adapter.load()` does `JSON.parse(JSON.stringify(...))` to deep-clone on every load. Store actions clone before mutating — never `Object.assign` on a loaded reference.
2. **Input focus loss**: Uncontrolled inputs with `defaultValue` throughout. Store updates do not cause the input's parent to re-render if the selector is properly scoped.
3. **Save debouncing**: 800 ms debounce on the Zustand subscriber. Saves are always triggered; the debounce just batches rapid changes (e.g. stepper taps).

## Accessibility

- All interactive elements have visible focus rings (`:focus-visible` with `outline: 3px solid var(--accent)`).
- Minimum tap target: 44 px height on all buttons and checkboxes.
- Stepper buttons: `aria-label` includes the direction and what it adjusts.
- Done-toggle buttons: `aria-pressed` reflects state.
- Rep inputs: `<label>` via `htmlFor` linkage.
- PhotoViewer: `role="dialog" aria-modal="true" aria-label="Session photo"`.
- Charts: sparklines are `aria-hidden`; body-weight chart has `role="img"` with descriptive `aria-label`.
- Toast: `role="status" aria-live="polite"`.
- Tab nav: `aria-current="page"` on active tab.
